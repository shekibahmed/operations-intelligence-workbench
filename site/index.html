Trust

How the AI is kept honest

These are screens from the running demo. Each one shows a control that stops a model’s guess from quietly becoming a fact.

Every claim cites its evidence, and uncertainty goes to a person

  • Evidence and confidence. Each extracted field keeps the exact source segment, the extractor’s identity and version, and a confidence. With no support, it says so instead of inventing a value.
  • Review queue. Low-confidence or ambiguous fields wait. The reviewer sees the raw source, the candidate value and the cited span, then accepts, corrects or rejects.

Rules are deterministic and show their working

  • Closed fact catalogue. Rules cannot run arbitrary expressions. They read named facts the pack defines.
  • Visible trace. Every firing shows the facts it evaluated and the condition tree that matched, so a reviewer can see exactly why a case was opened.

Approval is a recorded human act

  • Proposals only. Providers and rules can propose a decision. They cannot approve, execute or change workflow state.
  • Enforced, then attacked. A high- or critical-risk decision cannot reach approved without a separate approval record. This is enforced in application code and the database, and tested with bypass, replay and injection attempts.

Everything lands in an audit trail

  • Append-only. Actor, subject, timestamp and causal links for each material step.
  • Corrections add, never rewrite. A correction appends a new entry and re-evaluates. History stays as it was.

Straight answers about what this is

  • All data is synthetic. Sites, assets, people and documents are fictional.
  • The demo provider is deterministic. Each fixture maps to a recorded expected extraction, so there is no live model call and no API key. The interface can take a live provider; none is wired in.
  • Demo approvals are scripted. They show the control working inside a synthetic app. They do not stand for physical work or measured results.
  • No customer results or ROI claims. Dashboard figures are labelled observed, calculated, estimated or hypothetical, and a hypothetical figure is never shown as an outcome.

MCP server

Read-mostly tools over scenario packs, fixtures and the evaluation harness, over stdio. Clone the repo, run pnpm build, then register it:

{
  "mcpServers": {
    "oiw": {
      "command": "node",
      "args": ["packages/mcp-server/dist/cli.js"]
    }
  }
}

Author a pack

A new industry is a directory, not a fork. The guide documents the validator-enforced contract in authoring order, with a scaffold command and a template that already validates.

pnpm pack:scaffold my-pack --name "My Pack" \
  --description "What it covers"
pnpm validate:packs && pnpm eval --pack my-pack

Adversarial fixture corpus

Every pack ships edge-case artifacts with gold outcomes: missing identifiers, conflicting dates, ambiguous references, negation, duplicates, and prompt-injection text hidden in chat, CSV, JSON and PDF content. Use them to test your own extractors.

Run it

Four commands to your own copy

The guided tour creates an isolated, seeded guest workspace on first click. You need Node 22, pnpm 11 and Docker for the local Postgres.

{{LIVE_DEMO_LABEL}}

git clone https://github.com/shekibahmed/operations-intelligence-workbench.git
cd operations-intelligence-workbench
pnpm install && docker compose up -d && pnpm db:migrate
pnpm dev   # then open http://localhost:3000/demo
