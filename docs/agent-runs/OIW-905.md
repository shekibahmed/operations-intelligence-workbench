## Assumptions and deviations

- **Shared-database test run**: this machine hosts four worktrees
  (`oiw-core`, `oiw-ux`, `oiw-packs`, `oiw-quality`), each with its own
  docker-compose Postgres project, but only one can ever bind host port
  5432 at a time; at the time of this session `oiw-core-postgres-1` held
  that port and this worktree's own `oiw-quality-postgres-1` container was
  running without a published port. `pnpm test` was run once against the
  bound (`oiw-core`) database to get a genuine, full-suite pass/fail signal
  under the `SESSION.md`-documented default `DATABASE_URL`; every other
  verification in this session (migrate/seed/reset/dev-server/`pnpm eval`)
  used a disposable, isolated container on a non-default port specifically
  to avoid touching any other worktree's shared state. `pnpm test`'s
  integration suites create randomly-identified workspaces and do not
  appear to have left any observable side effect, but flagging the shared
  read/write for the lead's awareness since it wasn't a fully isolated
  verification.
- **PR title `/adapt` claim**: the task packet says the professional-
  adaptation link is "a placeholder pointing at `/adapt` (destination
  decided by owner)." The `/adapt` route and its intake form already exist
  in `apps/web` (merged under OIW-201) but have no backend — no persistence,
  no analytics event (FR-120/FR-121 are explicitly gated on an owner
  decision per `SESSION.md`, staged as OIW-904). `README.md` documents this
  distinction explicitly (both that the route exists today and that it has
  no backend yet) rather than either overclaiming a working CTA or omitting
  the route's existence.
- **Repository-public claims**: `SESSION.md` records the repository as
  private until M3 and Wave 5 deployment (Vercel/Supabase) as gated on owner
  action. `README.md`'s Status line and "What is intentionally excluded?"
  section state this plainly rather than writing hosted-demo copy that would
  be aspirational at the time of this PR.
- **Test-count figures**: deliberately did not restate `SESSION.md`'s
  "375+ tests, 22 e2e specs" figure in `README.md`/walkthroughs verbatim,
  since re-running `pnpm test` in this session actually produced 395 (a
  different, larger, but consistent-with-growth number) and Playwright specs
  were not re-run to get a trustworthy current count. Where a number is
  cited, it is one this session verified directly (the `pnpm eval` 1.000
  result, the `pnpm test` 395/395 result); where it isn't verified,
  documentation names the spec *files* by relative path instead of a count.
