## Architectural decisions
- **"Benign twin" proven structurally once, not per-fixture.** The task
  packet's functional requirement #2 ("no rule fires that would not fire on
  the benign twin") could have been implemented as 27 hand-paired
  fixture-diff tests. Instead, `rule-fact-neutrality.test.ts` proves it once,
  architecturally: the rule engine's `FactReferenceSchema` (amendment A2) is
  a closed three-kind union with no field that can read raw artifact text,
  warnings, or the source reference — so *no* fixture, injected or benign,
  can differ in rule-firing behaviour based on its raw text, by
  construction. This is stronger than per-fixture pairing (it also covers
  every *future* fixture, not just this task's 27) and avoids inventing 27
  synthetic "benign twin" fixtures that would have duplicated fixture-count
  growth for no additional assurance. Documented in
  `INJECTION_TEST_MATRIX.md` §2 item 2 with the rationale.
- **New fixtures are deliberately isolated, not narrative-linked.** Unlike
  the pre-existing `edge-006` fixtures (which tie into each pack's ongoing
  demo story — e.g. asset-reliability's `A-142` already has an approved
  hold-from-service Decision by the time `edge-006` runs), all 27 new
  fixtures use fresh, previously-unused identifiers (`A-901..908`,
  `B-9001..9008`, `VLP-INJ-2026-0901..0908`) and set
  `expectedEventType: null` / `expectedEntities: []` /
  `expectedCaseLinkage: false` in gold. This was a deliberate scope
  reduction: it keeps 27 new fixtures simple and independently verifiable
  (each fixture is its own `it()` inside an isolated per-fixture workspace)
  rather than requiring each one to be woven into three separate
  multi-artifact storylines. Confirmed via `packages/evals/src/runner.ts`
  reading that `expectedEventType`/`expectedEntities`/`expectedSignals`/
  `expectedCaseLinkage` are only cross-checked against real pipeline output
  for the `smoke` fixture set (never for `edge-cases`), so this is
  consistent with how the scoring harness already treats the edge-case set.
- **Homoglyph fixtures target real seeded entities, not invented ones.**
  Initially generated `document-assurance-edge-015` with a synthetic,
  never-seeded reference (`VLP-INJ-2026-0916`) — a homoglyph of nothing,
  which would make the "does not silently conflate with the real entity"
  assertion vacuous. Caught before committing (confirmed
  `scenario-packs/document-assurance/seed/entities.json` has no such entity)
  and regenerated to target the pack's real `VLP-FAL-2026-0142` (Project
  Falcon MSA) entity instead, matching how the asset-reliability (`A-142`)
  and process-exceptions (`B-2205`) homoglyph fixtures were already
  correctly designed against real seeded entities.
- **CSV/JSON/PDF fixtures reuse already-proven schemaKeys and artifactTypes**
  per pack (e.g. asset-reliability's `asset-identifier`/`requested-action`/
  `service-status`, all plain-`string`-typed per their JSON Schema) rather
  than introducing new observation schemas — this is a test/fixture task
  with no `packages/*` schema-authoring scope, and reduces the risk surface
  for `validate:packs`/`pnpm eval` since these schemaKeys already have a
  proven-valid shape.

  branch's point-in-time (confirmed via `SESSION.md`'s "Wave 4 batch B"
  entry listing OIW-811 ∥ OIW-805 as parallel, unordered tasks, and via

- **e2e coverage is a representative subset, not all 30 fixtures.** Running
  all 30 fixtures through full-page Playwright navigation would be slow and
  redundant: the DOM-safety mechanism (React's default text-escaping, no
  `dangerouslySetInnerHTML`/autolinking anywhere in the five rendering
  surfaces — confirmed by reading `technical/artifacts/[id]/page.tsx`,
  `review/page.tsx` + `ReviewQueuePanel.tsx`, `cases/[caseId]/page.tsx` +
  `CaseNotes.tsx`, `entities/[entityId]/page.tsx`, `audit/page.tsx`, and
  `highlight-text.tsx` in full) is identical for every fixture regardless of
  payload shape. `injection.spec.ts` covers one fixture from each
  rendering-risk class (instruction-message, HTML/script, markdown/link,
  oversized-Unicode, homoglyph) against the asset-reliability pack, across
  both the Technical Inspector (unconditional full-raw-text render) and the
  Review Queue (conditional on review routing) surfaces. Full per-fixture,
  per-pack, per-surface coverage of *behaviour* (not rendering) is achieved
  by the dynamic product-level suite (`product-injection-matrix.test.ts`),
  which does cover all 30 fixtures × all 3 packs.
- **No product defects found.** Every assertion in both new test suites
  passed against the existing, unmodified pipeline. Per the task packet,
