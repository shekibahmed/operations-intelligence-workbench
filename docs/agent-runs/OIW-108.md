## Architectural decisions

- Retained the pack-authored vocabulary. `displayName` is the label required by
  the packet, while optional `entityType` is the entity-link hint. Introducing
  parallel `label` or `entityLink` aliases would have duplicated the actual pack
  semantics.
- Kept `valueType` aligned with the shipped top-level categories
  (`string`, `number`, `object`) and added the explicitly authorized boolean
  category. Enum and date remain string constraints, and JSON Schema `integer`
  remains a constrained numeric value, exactly as shipped.
- Implemented only the JSON Schema subset present in the three packs plus the
  packet's boolean requirement. Unsupported keywords fail closed during pack
  validation rather than being silently ignored.
- Defaulted `evidenceRequired` to `true` during contract parsing. This provides
  a required typed evidence expectation without changing the meaning or bytes
  of real pack files and matches the platform provenance rule.
- Exposed `ReadonlyMap<string, ObservationSchemaDefinition>` on the loaded pack
  and an additive `getObservationSchema` helper. Duplicate schema keys make a
  pack invalid, preventing ambiguous catalogue lookup.

These decisions are recorded in ADR-009.
