## Architectural decisions
- Application services define narrow structural ports and consume the public
  persistence/Scenario SDK implementations through dependency injection. This
  keeps application orchestration framework-neutral, avoids pack filesystem
  parsing and requires no new dependency or lockfile change.
- Fixture Sources are deterministically grouped by artifact type plus canonical
  source metadata. Source and Artifact UUIDs derive from Workspace ID plus
  stable fixture keys, preventing global primary-key collisions while making a
  reset of the same Workspace exactly reproducible.
- Seed-managed record timestamps use one fixed demo epoch; lifecycle Audit
  Entries use operation time. Reset/reseed audits are separated by one
  millisecond so persistence's timestamp/ID ordering preserves the hash chain.
- Reset loads and validates the entire fixture plan before calling the public
  atomic `clearForReset` boundary. Historical audits remain append-only; exact
  equality applies to the operational seed state as required by OIW-107's
  approved audit semantics.
- HMAC tokens contain only version, opaque session UUID, Workspace UUID and
  issued/expiry times. Verification accepts an ordered secret set for safe key
  rotation and never trusts a client Workspace selector.

No new ADR is required; these implement ADR-004 and ADR-007 through the merged
OIW-107 boundaries.
