## Architectural decisions
- Optional content uses `<!--requires id=X all|any=path,...-->` comment blocks in `index.html`, resolved by the build against the assembled tree. This keeps the page valid HTML for editing, and means a late-arriving MP4, poster, caption, music file or `llms.txt` appears on the next build with no edit.
- `{{LIVE_DEMO_URL}}` / `{{LIVE_DEMO_LABEL}}`: when no URL is configured the primary button reads "Run the demo locally" and points at the README quick start, so the page never claims a hosted demo that does not exist.
- Background music: the `<audio>` has no `controls` and no `autoplay`; the toggle button carries the `hidden` attribute until JS runs (`.music__btn[hidden]` forces `display: none`, since the button's own `display` rule otherwise overrides the attribute) and is hidden again if the audio fails to load, and a `<noscript>` native-controls audio is the fallback. Playing a video pauses the music and vice versa.
- The pipeline is an HTML/CSS diagram (not one SVG) so the same markup lays out horizontally on desktop and vertically on phones. The packet and the lit rings run on one 18 s CSS clock using only `transform` and `opacity`. Reduced motion removes the packet and shows every ring still.
- System font stack. Inter (352 KB) was not vendored, to keep the page light.
- Pages workflow is split into build and deploy jobs (standard Pages pattern). Environment variable `LIVE_DEMO_URL` is passed through `env:` rather than inlined in the shell command.

## Assumptions and deviations
- Release trigger: the `github-pages` environment only accepts `main`, but a `release` event runs on the tag, where the deployment would be rejected. For that event the workflow runs a small `redispatch` job that calls `gh workflow run pages.yml --ref main`; build and deploy are skipped on the release event itself. Deviation from "on release: published => build and deploy", needed for it to work. Uploading assets to an existing release does not emit `published`; use workflow_dispatch after refreshing `media-latest`.
- Asset names the page expects from OIW-913: `media/{trailer,asset-reliability-tour,process-exceptions-tour,document-assurance-tour}.mp4`, captions `media/<same name>.vtt`, posters `media/poster-{trailer,asset-reliability,process-exceptions,document-assurance}.jpg`. A missing caption or poster is dropped; if the names differ the video blocks (or their tracks) are hidden. `poster-trailer.jpg` and `trailer.vtt` are guesses, since the packet marks `trailer.vtt` as optional.
- Music credit: the footer links to `docs/media/CREDITS.md` on GitHub (rendered) and the file is also copied to `_site/media/`. The footer says "public-domain recording" per the OIW-911 requirement; adjust the wording if the licence turns out to be CC0 rather than public domain.
- The MCP config snippet (`node packages/mcp-server/dist/cli.js`) and plugin commands (`oiw-pack-authoring@oiw`) come from the OIW-912 packet; the links to `packages/mcp-server` will 404 until that merges.
