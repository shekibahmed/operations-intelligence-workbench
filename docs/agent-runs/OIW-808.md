## Architectural decisions

- Extracted `BUTTON_BASE_CLASSES`/`VARIANT_CLASSES` from `Button` rather
  than adding an `as="a"` polymorphic prop: every affected call site
  needed a real `<a>`/`Link`, not a styled `<button>` that happens to
  navigate, so a shared class-string export is simpler than a
  polymorphic-component abstraction for four call sites.
- Reduced-motion support went into `globals.css` as a blanket
  `prefers-reduced-motion` media query rather than a per-component prop,
  since it's a standing user preference that should apply uniformly, not
  something each new component has to remember to opt into.
- The tablet drawer uses `xl:contents` on a wrapper `div` around the
  toggle button and nav, rather than duplicating the nav markup for two
  breakpoints: `contents` drops the wrapper from the box model at `xl:`
  and up, so the toggle and nav rejoin the three-column grid as direct
  children with no duplicated JSX.
- `about-pack`'s stub-data replacement reuses the existing
  `findPackEntry` server helper rather than adding a new one — it's the
  same lookup `technical/rules/[id]` already performs, just consumed for
  a listing instead of a single record.

None of these rise to ADR-worthy: they're implementation choices inside
an already-scoped remediation task, not new architectural boundaries.

## Assumptions and deviations

- **Session continuity deviation, not a task-packet deviation.** The
  implementation work referenced in this handoff (all fixes, the tablet
  drawer, the new axe spec, the 16-fix-site set) was done by a prior
  agent session on this same worktree/branch, left uncommitted. That
  session detached a background verification scan and ended its turn
  expecting to resume from the detached process's output — in this
  harness's headless mode, ending a turn terminates the session, so the
  detached scan's result was never collected and the session could not
  resume. This session picked up the uncommitted worktree state exactly
  as left, independently re-verified every acceptance criterion from
  scratch (see Tests run and results), found and fixed one additional
  defect the re-verification itself surfaced (`/demo` missing `<h1>`),
  and is the one that commits, pushes and opens the PR. Lesson for future
  runs, already load-bearing: never detach long-running verification
  work and end the turn expecting a resume — in headless mode there is no
  resume.
- Treated "capture the moderate/minor baseline" as capturing the true
  current state (which turned out to be empty after the one additional
  fix), not as transcribing whatever a single scan happened to return —
  a stale `page-has-heading-one` baseline entry would have been a
  documented "deferral" for a defect that was actually just unfixed.
  Fixing it took one line and matched an existing, unambiguous
  `<h1>` convention used by every other page in the app, so this run
  treated it as in-scope for "fix what it finds" (task packet Objective)
  rather than something to defer to a follow-up.
- No dependency requests beyond the one permitted addition
  (`@axe-core/playwright`), already added to `apps/web/package.json` and
  the lockfile.
