## Architectural decisions
- ADR-013. The delete exception is structural (an Approval may be deleted only once its parent Decision or Workspace is gone, which is exactly the FK cascade) rather than a `SET LOCAL oiw.allow_governance_purge` flag. No application code changes were needed. The flag was rejected because any SQL writer can set it.
- Blank test is a regex bracket expression: `[:space:]` plus an explicit, escaped set of Unicode spaces and invisible code points (ADR-013), not `btrim`, because `btrim` strips only the space character.
- `audit_entries` was already append-only at the database level (`audit_entries_append_only`, migration 0000), with workspace deletion disabling the trigger inside one locked transaction. No change.

## Review follow-up (round 2)
- Blocking, Unicode bypass: confirmed. `[:space:]` on `en_US.utf8` did not cover U+2007, U+202F, U+1680 or U+180E, so those passed the CHECK and the gate. Fixed: the bracket set is widened (NEL, U+00A0, U+1680, U+180E, U+2000-U+200F, U+2028-U+202F, U+205F-U+2060, U+3000, U+FEFF) and written with regex escapes so the migration, `schema.ts`, the drizzle snapshot and ADR-013 are textually identical and contain no invisible characters. `blankApprovers` now pins U+2007, U+202F, U+1680, U+180E, U+2003, U+3000 and U+0085. ADR-013 states that code points outside the set still rely on the server locale's `[:space:]`. Migration 0004 is unreleased (this PR), so it was edited in place; `pnpm db:generate` reports no schema drift.
- Verifier: e2e, build and eval were not run before. Now run: `pnpm build` pass, `pnpm eval` all 1.000, `(cd apps/web && pnpm test:e2e smoke north-star security)` 9 passed.

## Known limitations / follow-up
- The Approval contract is `approver: z.string().min(1)`, which still accepts whitespace-only strings; the database now rejects them. A contract-change task could add a non-blank refinement so the failure surfaces as a validation error rather than a database error.
- Deleting a whole Decision also deletes its Approvals. Consider a production-role privilege split (no DELETE on `decisions`/`approvals` for the application role) as deployment hardening.
