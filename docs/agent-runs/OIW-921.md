## Blocker
Exact blocker: the rule description is frozen in `casebook/sources.json` (`approval-rule`), and
`recording.json` `inputs[]` pins the sha256 of `sources.json` (and `case.json`, `scripts/casebook/capture.ts`,
the capture Playwright config and spec). `loadCasebook` (`scripts/casebook/evidence.ts`) requires the
pinned `sources.json` hash to match the bytes on disk, so any `sources.json` edit makes
`pnpm casebook:check` and `pnpm build` fail. README step "Publishing changed `case.json` or
`sources.json` inputs requires a deliberate fresh recording" confirms the only supported path is
re-capture.

The documented capture command would be:
`CASEBOOK_ADMIN_DATABASE_URL='<isolated postgres admin URL>' pnpm casebook:capture`
Consequences: (a) it rewrites `recording.json` entirely (new `capturedAt`, `captureRevision`,
`sourceRevision`, input hashes, stages), replacing the recorded history; (b) the capture preflight
(`scripts/casebook/capture.ts`) requires each frozen source to equal `git show <sources.sourceRevision>:<path>`,
and `sourceRevision` is `d39191038fbe626e6afdd4a54b3a87d2e98cb0e9`, whose rule file has the old
description, so capture fails with "Historical source does not match frozen evidence: approval-rule"
unless the historical evidence revision is changed, which the README forbids doing merely to point at
a newer commit; (c) browser tests hard-code the captured revision and would need deliberate review.
Hand-editing the pinned hash or the HTML would falsify the recorded evidence and is prohibited.

Required upstream decision: either (1) approve a fresh capture with a new pinned evidence revision
(a separate, larger task owning `recording.json`, capture inputs and test expectations), or
(2) leave the casebook's frozen rule text as the historical wording and change only the live rule
description plus a loader exception, which needs a design decision since the frozen `approval-rule`
copy must equal the live file at capture time, or (3) accept the wording as is and fix only the live
guided-tour display via a pack label if one exists.

Files affected if unblocked: `approval.rules.json`, `casebook/{sources.json,recording.json,README.md}`,
`apps/web/public/casebook/a-142-repeat-fault.html`, casebook browser tests.
Safest next action: lead decides between options 1 to 3; no repository state needs cleanup.
