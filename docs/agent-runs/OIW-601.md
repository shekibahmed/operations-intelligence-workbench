## Architectural decisions

- Used the existing public Workspace-scoped repository `list` ports through a
  structural application interface. No persistence internal, migration or
  read-model addition was required.
- Used absolute time-window bounds and an injected clock. This keeps evaluation
  reproducible while allowing SLA status to be evaluated at a caller-selected
  instant.
- Monday-based UTC weeks and stable sorted output remove locale/order variance.
- Kept pre-v1.5 `MetricDefinition` compatibility additive for the existing web
  stub, while requiring `MetricDefinitionV15Schema` at the Scenario Pack and
  evaluator boundaries. ADR-012 records this distinction.
- Hypothetical evaluation branches before repository selection and has its own
  result discriminator, making the no-operational-computation rule structural.

## Assumptions and deviations

- Legacy pack aggregations outside the authorized v1.5 families were
  mechanically represented by the closest fixed family while retaining each
  Metric ID, name, description, classification and format. The v1.5 service
  intentionally does not implement arbitrary ratios, event-to-event duration
  joins or feed queries; typed result kinds expose the actual bounded output.
- Test-pack Metric files and their dashboard references were mechanically
  normalised because loader enforcement otherwise would obscure the intended
  failure mode of those fixtures.
- No prohibited path, `SESSION.md`, task packet, migration or lockfile changed.
