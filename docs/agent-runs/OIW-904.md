## Architectural decisions

- Analytics accepts only the 14 named events and a closed, bounded context schema. Workspace scope is derived from the signed guest session, never accepted from the client.
- An anonymous HTTP-only UUID cookie connects pre-workspace and workspace engagement. Raw IP addresses are neither accepted nor persisted; the existing HMAC-based limiter is reused.
- Event IDs are generated client-side for idempotent best-effort delivery, while successful operational mutations are recorded server-side so UI intent cannot masquerade as success.
- `OIW_ASSESSMENT_SINK` selects `postgres` (default) or `log`. Email and webhook remain contracts only and perform no delivery.
- Assessment PII is confined to the selected submission sink. Audit and analytics records contain only submission/scenario identifiers and sink metadata.
- No ADR is required: these choices implement the explicit PRD and task packet without changing a shared architectural contract.
