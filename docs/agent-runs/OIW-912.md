## Architectural decisions
- **Tool surface.** Every tool returns one `text` content block of compact JSON; failures set `isError`. Read tools build the registry per call so a scaffolded pack is visible immediately.
- **`list_fixtures` for agent builders.** Default set is `edge-cases`. Each artifact carries type, sha256, byte length, source metadata and `expectedOutcome` (the pack's gold entry minus `fixtureId`, or `null`). Raw bytes are opt-in (`includeContent`) and are returned under the key `untrustedContent` (utf8, or base64 if not valid UTF-8); the authored expected extraction is opt-in (`includeExtraction`). `artifactIds` filters. The tool description and a `notice` field in the reply state that artifact text, source metadata and gold notes are untrusted data, not instructions. Gold is located by the manifest's `evaluationSets` entry named `<set>.gold.json`; its shape is a pack convention (PACK_AUTHORING section 9), so an unreadable file yields a warning rather than an error.
- **Process spawning.** `validate_packs`, `run_eval` and `scaffold_pack` use `execFile("pnpm", [...])`, never a shell, with timeouts and an output cap. The runner is injectable so tests assert the exact argument arrays. `run_eval` reads `packages/evals/eval-results.json` (gitignored) to return structured scores, ignoring a file older than the run.
- **Write gate.** `scaffold_pack` checks `OIW_MCP_ALLOW_WRITE=1` first, then validates the id against `^[a-z0-9]+(-[a-z0-9]+)*$` (and rejects `template`) in the handler, so the refusal is a normal tool error and no process starts. `run_eval` validates its optional pack id with the same pattern before it can reach a command line.
- **Zod.** `@modelcontextprotocol/sdk` 1.32.1 accepts zod 3.25+ and 4; it works with the repo's zod 4 and no package-local pin was needed.
- **Dependency direction.** `@oiw/mcp-server` depends on `@oiw/scenario-sdk` and zod (the unused `@oiw/contracts` dependency and project reference were removed in the review-fix pass); it is added to the neutral-core scan list and contains no pack ids or industry terms. Tests discover packs dynamically.
- **Seed issues.** Each of the six seed issues in `docs/contributing/FIRST_CONTRIBUTIONS.md` points at a gap checked in this worktree: (1, 2) edge-case classes that `asset-reliability` has and `process-exceptions` / `document-assurance` lack, (3) evidence locators derived from the extraction itself (`packages/evals/README.md`, `packages/evals/src/runner.ts`), with all 285 `text-range` locators confirmed to match their excerpts, (4) a scaffolded pack fails `pnpm eval --pack` (reproduced: `ENOENT` for a missing gold file), (5) stale artifact counts in three `narrative/edge-cases.md` files, (6) the "tolerated until OIW-004b lands" message. No GitHub issues were created.
