## Architectural decisions
- **Lens resolution is server-side, not a client Context.** Each
  `/w/[workspace]/*` page reads `searchParams.lens` directly; if missing or
  invalid it `redirect()`s to the canonical URL (UX_SPEC §1.3 default-per-
  section, with Decision Centre falling back to the `oiw-last-lens` cookie).
  This means most pages need no client-side lens plumbing at all — only the
  segmented control (`LensSwitcher`) and a tiny cookie-sync effect
  (`LensCookieSync`) are client components. Simpler and less client JS than
  a global lens Context.
- **No `/technical` list route exists** (UX_SPEC's route table only defines
  the two dynamic detail routes, R12/R13). The Technical nav item's
  Artifacts/Rules submenu links to a fixed default id
  (`apps/web/src/lib/nav-defaults.ts`) rather than a list page — documented
  as a UX_SPEC-driven choice, not an omission.
- **`?state=default|empty|loading|error`** is the mechanism for reaching the
  non-default states UX_SPEC §5 requires per screen, since there is no live
  backend yet to produce them from real request failures (OIW-201 non-goal).
  Documented in `apps/web/README.md` and `apps/web/src/types/screen-state.ts`.
- **Pack-label shape (`PackLabels`) is a local `apps/web` type**, not a
  contract. `packages/contracts`' `ScenarioPackManifestSchema.labels` is only
  a *path* to a pack's labels file (frozen; not edited) — the label
  document's own shape isn't part of the Wave 0 freeze. `apps/web` renders
  from a typed stub instance now; Wave 2's pack registry will supply the real
  thing against whatever schema OIW-104 defines.
- **Case Detail / Entity Detail two-column reflow** uses explicit CSS Grid
  placement (`xl:col-start-*`/`xl:row-start-*`) on a single flat list of
  sections in the *tablet* order UX_SPEC's wireframes specify verbatim, so
  one DOM order serves both the correct tablet single-column sequence and
  the desktop two-column layout without duplicating content.
- **Radix UI primitives** (`@radix-ui/react-dialog`, `@radix-ui/react-tabs`)
  back the two places accessibility behaviour is hard to get right by hand:
  the high-risk Decision approve/reject confirmation (focus trap + return,
  PRD §22.4/UX_SPEC §5.11) and the Artifact/Rule-trace tab strip.

## Assumptions and deviations
- **One fixture dataset, not per-pack.** All `/w/[workspace]/*` routes render
  the same Asset Reliability stub dataset regardless of the `workspace` URL
  segment or which pack was selected on `/demo/[pack]` — there is no
  workspace-creation backend yet (Wave 2). The `workspace` segment is still
  genuinely dynamic (routes are parameterised, not hard-coded), it just isn't
  looked up against real state. Documented in `apps/web/README.md`.
- **Stub narrative content is original**, not copied from
  `scenario-packs/asset-reliability/narrative/` (which is a prohibited path
  for this task and belongs to a different pack track/track's fixture
  format). It tells a consistent, self-contained story (asset AR-1042,
  repeat brake-assembly fault) purely for demonstrating the shell's layout
  and states — no product behaviour was invented beyond what UX_SPEC
  specifies.
- **Action-item checkbox toggling, review-queue actions, and decision
  approve/reject are client-local simulations** (no persistence) — this
  task's non-goals exclude real data fetching/mutation. State resets on
  reload, as expected for a stateless static demo.
- **`?entry=` link from a rule trace's "Linked audit entries" to the Audit
  Explorer** just scrolls/highlights the matching entry client-side (no
  separate filtered view) — a reasonable minimal reading of "jump to Audit
  Explorer filtered to this execution" given Audit Explorer's filter bar
  itself is out of this task's interactive scope (list/read only).
- Root `package.json`: added `dev` and extended `test` (see Changed files).
  `eslint.config.mjs`: extended TS rule block to `.tsx` and added ignores —
  both changes are additive/backward compatible with the existing
  `packages/*` lint/typecheck/test setup (re-verified: `packages/contracts`'
  own tests and typecheck still pass unchanged).
