## Architectural decisions

- The application orchestrator owns narrow structural ports for adapters,
  providers, catalogue validation and routing. Runtime packages satisfy these
  ports without making `@oiw/application` depend outward on ingestion,
  intelligence, Scenario SDK or persistence implementations.
- Exact duplicates are workspace-scoped by the existing database uniqueness
  invariant and are represented by the returned link plus an append-only Audit
  Entry. Existing immutable Artifact metadata is not rewritten.
- Adapter-level segments preserve the parsed source structure. When a provider
  cites a narrower evidence excerpt, processing verifies it against the raw
  Artifact and persists a precise segment for the Observation.
- The sensible default confidence threshold is `0.75`; values below it route
  to review and values at or above it do not require review. A pack-authored
  `confidenceThreshold` overrides the default. Insufficient evidence always
  routes to review; negated findings use the same threshold rule.
- Complete provider payloads are revalidated at runtime even though the
  provider is typed. Extracted values and alternative candidates use the active
  catalogue's `validateObservationValue`; normalised values remain preserved
  provider provenance because shipped packs may intentionally normalise to a
  different representation.
- The fixture provider loads only through public Scenario SDK APIs, tolerates
  a duplicate checksum only when the extraction is byte-semantically identical,
  and rejects nondeterministic metadata, empty traces, conflicting mappings and
  misses.
- CSV parsing follows ordinary quoting and also applies a generic, documented
  recovery for unquoted commas in the penultimate narrative cell, required by
  a shipped smoke fixture. Short/missing-cell rows still fail closed.

## Known limitations / follow-up

- Binary PDF parsing remains deferred by amendment A7; the P0 adapter accepts
  fixture text with explicit page markers.
- The frozen Observation contract stores one `evidenceSegmentId`; processing
  therefore links the first verified evidence item. Current smoke and required
  edge fixtures each contain at most one evidence item per proposal. Supporting
  multiple persisted Observation evidence links requires a dedicated contract
  and persistence task.
- Persistence exposes repository operations rather than a cross-repository
  transaction port. Deterministic segment/Observation IDs and final-state
  idempotency make retry safe from duplication, but a future transaction API
  may tighten all-or-nothing processing semantics.
- Live model providers, entity resolution, Events, rules, Cases, Decisions and
  UI remain in their assigned follow-up tasks.
