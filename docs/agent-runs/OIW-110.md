## Architectural decisions

- Event ambiguity is evaluated from actual selection inputs: the unordered
  required Observation keys, finite required value constraints, and a primary
  Entity mapping only when that mapped key is itself required. Optional
  composition and occurred-at mapping do not make two selection predicates
  distinct.
- Existing semantic keys resolve every Asset Reliability and Process
  Exceptions collision. No artifact-type, filename, gold-set or pack-ID
  inference was introduced.
- Document Assurance genuinely cannot separate clarification, routine sign-off
  and inert correspondence by key presence: each uses `review-status`. The
  minimal additive v1.4 value constraint preserves the authored distinctions
  (`resolved`/`unresolved`, `no-escalation-needed`, `not-accepted`) without a
  new domain-specific key or executable predicate.
- Discriminator values are validated against the referenced pack Observation
  schema during pack load, so a contract-valid JSON value of the wrong pack
  type still fails with a path-annotated diagnostic.
