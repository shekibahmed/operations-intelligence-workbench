## Architectural decisions

- The CLI creates a process-unique database, applies repository migrations,
  and drops it in `finally`; evaluation cannot contaminate the normal demo
  database and failures still clean up.
- Pipeline orchestration lives behind additive `@oiw/test-support` helpers so
  the evaluator does not duplicate service construction, ingestion, review,
  advancement, seeding or migration logic inside `@oiw/evals`.
- Scoring is pure and separate from pipeline execution. This permits exhaustive
  sabotage tests without mutating real pack content or bypassing public
  services.
- Scores aggregate passed/total observations rather than averaging per-pack
  percentages, preventing small packs from receiving disproportionate weight.
- Text-range evidence accepts the specified ±5-character tolerance only on the
  same source line; structured locators require exact equality.

No ADR is required: these decisions implement the already-approved evaluation
design and remain inside the evaluation/test-support boundaries.

## Assumptions and deviations

- The merged gold JSON has no independent evidence-locator field, despite the
  OIW-005 design expecting one. The checksum-validated expected-extraction
  companion is therefore the evidence oracle. This follows amendment A1 and
  does not invent a second pack schema.
- The merged gold has no exact expected case state. Case-state scoring uses
  authored smoke linkage plus workflow-state validity, then validates the demo
  lifecycle's final states.
- Exact machine-readable entity/rule outcome assertions exist in the merged
  common lifecycle only for smoke gold. Demo and edge fixtures are still fully
  processed, but their gold cannot distinguish an outcome created by a fixture
  from later storyline reconciliation. Exact per-fixture entity/rule scoring
  therefore follows smoke gold; approvals are graded for every positive gold
  Decision across all sets.
- Byte-identical edge duplicates in two packs intentionally have narrative gold
  that differs from the original checksum's extraction. They are excluded from
  extraction scoring and graded exclusively through duplicate suppression.
- `docs/EVALUATION.md` specified lower historical tolerances for some fixture
  metrics; the task packet's stricter default `1.0` threshold is applied.

All deviations are also recorded in `packages/evals/README.md`.
