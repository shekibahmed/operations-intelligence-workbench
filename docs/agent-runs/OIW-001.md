## Architectural decisions

- Used plain pnpm workspace orchestration rather than Turborepo. The current
  graph is small, and pnpm already provides topological recursive execution.
- Runtime schemas live only in `@oiw/contracts`; `@oiw/domain` re-exports the
  inferred canonical types and is reserved for pure policy.
- TypeScript contract fields use camelCase. PRD snake_case examples are direct
  boundary translations; no semantic PRD field was dropped.
- Added fields required to make approved behaviour enforceable: Workspace
  expiry; Source scope/configuration; Artifact Segment identity/checksum;
  Entity aliases/timestamps; explicit Observation derivation, evidence and
  insufficiency state; Event assembler and re-evaluation state; Signal evidence
  and rule provenance; workspace scoping, evidence and timestamps on downstream
  records; and tamper-evident Audit Entry hashes. The full mapping is in
  `docs/DOMAIN_MODEL.md`.
- `ScenarioPack` v1 is the validated manifest shape. Loaded file contents are
  validated separately against the referenced shared schemas in later loader
  work.
- Fact catalogue v1 uses structured references rather than free-form fact
  strings, so unknown event fields, Observation selectors and aggregates fail
  at validation.
- Fixture extraction is keyed by lowercase SHA-256 and distinguishes extracted
  values from explicit insufficient-evidence results.
- ADRs 001–007 record modular-monolith, pack, provenance, deterministic fixture,
  approval, correction and guest-isolation decisions.
