## Architectural decisions

- A Decision has only one terminal human outcome in P0, so its Approval ID is
  now derived from Workspace + Decision rather than approver + outcome. An
  in-process keyed serialization gives the losing request a domain-status
  failure; the existing PostgreSQL primary key provides a cross-instance
  backstop. This preserves frozen contracts and avoids a migration.
- Proxy policy selects exactly one allow-listed header. It never falls through
  among attacker-controllable headers: Vercel chooses
  `x-vercel-forwarded-for`; a non-Vercel deployment chooses its edge-owned
  header explicitly or shares the conservative `unknown` IP bucket.
- Credential scanning remains a backstop, not secret management. Generic
  detection requires a credential-like assignment, at least 32 characters and
  Shannon entropy of at least 3.5, avoiding checksum noise; obvious test/local/
  placeholder forms are controls. Manual history/environment review remains a
  launch gate.
- The unsafe-write-back architecture guard is co-located with the credential/
  boundary checker because both are release-wide static gates and no second
  scanning framework is needed.
- No ADR is required: these changes implement already-approved PRD §22,
  amendments A2/A4 and the existing threat model without changing a shared
  contract, persistence schema or package boundary.

  the only filesystem-backed nested instruction found and read was

  Session pooler until a separately owned persistence change sets
  `prepare: false` and re-verifies the data layer.

  goal boundary. TLS, actual expiry scheduling, deployed rate-limit smoke,
  repository-history inspection and cross-task reviewer-record audit remain
  explicit launch operations, not threat rows left without disposition.
- The process-local rate-limit store is an explicit Accepted risk for the
  synthetic, no-upload public demo. It is not represented as a global limit on
