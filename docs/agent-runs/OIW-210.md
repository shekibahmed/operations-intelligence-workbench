## Architectural decisions
- **Session guard placement**: a single `src/app/w/[workspace]/layout.tsx` calls `requireWorkspace` so ADR-007's guard applies uniformly to every `/w/[workspace]/*` route — including the still-stub-marked ones — rather than only the three routes with real data. This was a deliberate reading of ADR-007 ("every server handler scopes queries by it") as a workspace-URL-wide guarantee, not just a guarantee for routes with real queries.
- **`React.cache()` for per-request dedup**: `requireWorkspace`/`getWorkspaceContext` are wrapped in `cache()` so the layout's guard call and a page's own call to fetch the resolved `Workspace`/`PackLabels` share one DB round-trip per request, without needing prop-drilling from the layout (Next layouts can't pass data to nested pages directly).
- **Fully-awaited pages + `loading.tsx`/`error.tsx`, not manual `<Suspense>`**: an earlier draft wrapped each real page's data-dependent section in a hand-rolled `<Suspense>` around an async child Server Component. This is incompatible with the existing unit-test harness (`routes.smoke.test.tsx` calls page functions directly and renders the returned element tree with plain `@testing-library/react`, which cannot mount an un-awaited async function component). Reverted to the original fully-awaited-page pattern and used Next's file-based `loading.tsx`/`error.tsx` conventions instead — real Suspense/error-boundary behavior in `next dev`/`next start`, with zero impact on the existing test-calling-convention.
- **Dev-mode session secret fallback**: `SESSION_SECRET` is required in production but auto-generated per-process in `next dev` if unset, so `pnpm dev` works with zero extra setup, matching "should feel immediate" (PRD §16.2). Documented in `apps/web/README.md`.
- **Real vs. stub scope beyond the packet's explicit list**: wired **Audit** to real audit entries (`workspace-seeded`/`workspace-reset`) and **About this pack**'s entity-types/event-types/workflows sections to the real pack registry, since both were already trivial extensions of work already in flight (same repository calls Overview needed; same `PackLabels` object every screen now receives) and meaningfully more honest than continuing to fabricate them. Kept About this pack's rules/metrics/dashboard-definitions sections stub-marked (no rule-execution or metric-aggregation engine yet).
- **Overview's three canonical stat cards** (Critical Signals / Open Cases / Pending Decisions) keep their UX_SPEC-defined semantics and now show a real, honest zero (fetched from real, empty `cases`/`decisions`/`signals` tables) rather than being repurposed into a proxy "artifacts processed" metric. A new **Workspace data** list card (an existing catalogue widget type, per A5) surfaces the real artifact/source counts the packet asked for.

## Assumptions and deviations
- **Rebuilt `packages/contracts` (and, for safety, all `packages/*`) dist output** via `pnpm --filter @oiw/contracts run build` / a repo-wide `pnpm -r --filter=./packages/* run build`. This was necessary to unblock the task at all: the checked-in (gitignored) `dist/` was stale relative to a merged fix (`a80c6e9`, "make manifest tours optional"), so `buildPackRegistry` loaded **zero** Scenario Packs and `pnpm demo:seed` failed with "Available packs: none" before any web-wiring work could be verified. This is a build-artifact regeneration, not a source edit under `packages/*`; flagging per the BLOCKED protocol's spirit even though the blocker resolved without needing to actually enter BLOCKED state.
- **Added `@oiw/application`, `@oiw/persistence`, `@oiw/scenario-sdk` as `apps/web` dependencies** (workspace-internal, `workspace:*`). The task packet's Prohibited Paths note "lockfile ... expected: none" for new deps, but consuming these packages' public APIs — the packet's own core requirement — is impossible without declaring them. `pnpm install` regenerated `pnpm-lock.yaml` with a 9-line, workspace-link-only diff; no external package was added.
- **Scope narrowed from "real Suspense per-widget"** to "real Suspense per-page" via `loading.tsx` (see Architectural decisions) — UX_SPEC's "each widget renders its own skeleton independently" is not fully realized; the whole page's data section streams as one unit. Documented as a known limitation rather than silently narrowed.
- **`/demo` and `/demo/[pack]` marketing copy** (`stubPacks`: problem statement, source types, example output, estimated length, lens summaries) intentionally left on stub data — this content has no equivalent field in the frozen `ScenarioPackManifestSchema` (id/name/description only), so there is nothing "real" to wire it to; only the **Start action** was wired to the real registry/workspace-creation path.
- **Segments render real-but-empty** on the Technical Artifact Inspector, since `SeedService` (an already-merged package, not owned by this task) only seeds `Source`/`Artifact` rows, no `ArtifactSegment` rows. Not treated as a gap in this task — segments are a real (if currently empty) repository query, consistent with "screens without upstream data stay stub-marked" not applying here since the *query* is real, only its current result is empty.
