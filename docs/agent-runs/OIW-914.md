## Architectural decisions
- Compose: removed `${VAR:?}` from `web` (evaluated even for inactive
  profiles). No default secret exists: the web command refuses to start with a
  `SESSION_SECRET` shorter than 32 bytes, in addition to the app's own refusal
  (`session.ts` throws in production when unset; `session-token.ts` rejects
  secrets under 32 bytes). `DATABASE_URL` is assembled in the shell wrapper to
  stay clear of the credential scanner. The postgres service now uses the same
  `POSTGRES_USER`/`POSTGRES_PASSWORD` (default postgres/postgres) as the web
  container; previously the service hard-coded them while `.env.example` implied
  they were configurable (a latent mismatch).
- `render.yaml` uses `autoDeployTrigger: "off"` instead of the packet's
  `autoDeploy: false`; Render documents `autoDeploy` as deprecated and the two
  are equivalent. Region `oregon` (Render default) paired with Neon AWS US West 2.
  `NEXT_PUBLIC_SITE_URL` is `sync: false` because the URL is not known until the
  service exists.
- Health check path is `/robots.txt` (database-free; there is no `/healthz` route).
- Keepalive pings `/` not `/robots.txt` (deviation from packet): Render docs say a
  spun-down free service answers `/robots.txt` with its own disallow-all page
  without waking the app, so a robots.txt ping could never wake it.
- `deploy.yml` guards: `workflow_run` only for `push` events from this
  repository (the job holds secrets; a fork PR branch named `main` must not
  qualify); `workflow_dispatch` only from `main`; checkout and Render deploy
  `ref` use the CI-validated SHA. Migrates when `DATABASE_URL` is set even if the
  deploy hook is not yet set (needed for owner step order: migrate before first
  Blueprint deploy).
- `expire-demo.yml`: also moved the dispatch input out of shell interpolation
  into an env var (`BEFORE`).
- Keepalive ends with a warning rather than a failure when the app never
  answers, to avoid alert emails every 10 minutes during an outage.

## Assumptions and deviations
- **Build-time env gap (needs a Dockerfile follow-up, outside owned paths).**
  Render converts service env vars to Docker build args
  (https://render.com/docs/docker) but the `Dockerfile` declares no `ARG`, so
  `NEXT_PUBLIC_SITE_URL` is not visible to `next build` on Render. Verified
  locally that the baked robots.txt points to localhost. Effect: no HSTS header
  from the app (Render's edge redirects to HTTPS) and wrong sitemap URLs. Fix is
  `ARG NEXT_PUBLIC_SITE_URL` + `ENV NEXT_PUBLIC_SITE_URL=$NEXT_PUBLIC_SITE_URL`
  in the build stage only (never an ARG for secrets). Documented in
  `docs/DEPLOYMENT.md` §9.4.
- **X-Forwarded-For residual on Render.** Render's docs are silent; a Render
  feedback thread reports it appends to a client-supplied chain, so the app's
  leftmost-entry read is spoofable (same accepted residual as Cloud Run).
  Documented in §9.5; `none` rejected as worse (single shared bucket).
- Render may add a name suffix if `oiw-demo` is taken; the doc covers updating
  `NEXT_PUBLIC_SITE_URL`/`RENDER_APP_URL`.
- Render's PORT: Render sets `PORT` (default 10000) and the standalone server
  honours it; the `Dockerfile` default of 3000 is overridden. Not set in the
  Blueprint.
- The 750-hour figure: keepalive window of 16 h/day is about 490 h/month.
