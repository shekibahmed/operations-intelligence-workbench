## Architectural decisions
- P0 uses a process-local `InMemoryTokenBucketStore`, but all policy depends on the small `TokenBucketStore` interface so a shared atomic implementation can replace it without touching Server Actions.
- Each authenticated guest mutation consumes two action-specific buckets: opaque session ID and HMAC-derived IP. Pre-session workspace creation necessarily has only the IP bucket; once a valid guest cookie exists, both apply.
- Rate-limit denial audit is separate from the rejected operational mutation. A workspace-scoped audit is appended at most once per mutation window; before a workspace exists, the equivalent structured server log is keyed only by the HMAC IP value.
- The existing persistence whole-workspace deletion port remains the audit-safe expiry boundary. No migration or alternate deletion path was added.
- Decision actions now use `ApprovalService` instead of duplicating approval persistence in the web layer. The service records outcome-specific action names so the existing Audit Explorer and tours remain semantically stable.
- The current no-upload public surface is treated explicitly: the restriction gate is closed only while no endpoint exists, with a reusable mandatory application policy ready for its future owner.
