## Functional Requirements
1. Drizzle schema for: workspaces, sources, artifacts, artifact_segments,
   entities, observations, operational_events, signals, cases, action_items,
   decisions, approvals, audit_entries (+ join/link tables as needed).
   Field shapes mirror `@oiw/contracts` v1.1 including negated evidence
   status, alternative candidates (JSON), and `conflicting` review status.
2. Every domain table carries `workspace_id` (non-null, FK, indexed) —
   workspace scoping is structural (A4/ADR-007).
3. Artifacts immutable by convention: no update path in the artifact
   repository beyond `processing_status`; checksum unique per workspace.
4. Audit entries append-only: repository exposes insert + query only.
5. Pack-specific attributes in validated JSONB columns (validated against
   contracts at the repository boundary, not raw writes).
6. Repository interfaces (ports) + Drizzle implementations for each object;
   all queries workspace-scoped by construction (workspace ID is a required
   argument, not an optional filter).
7. Migrations generated + committed; `pnpm db:migrate` and `pnpm db:reset`
   scripts; `docker-compose.yml` provides local Postgres.
8. Integration tests against real Postgres (docker); CI workflow extended
   with a Postgres service so they run on PRs. Tests must cover: round-trip
   per repository, workspace-scoping (cross-workspace read returns nothing),
   artifact immutability, audit append-only.
9. Keep `packages/persistence` free of industry terms (architecture:check
   must still pass).
