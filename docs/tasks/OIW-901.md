# Task OIW-901: Playwright in CI and e2e Determinism (Wave 5 start)

## Owner
Codex (high reasoning)

## Branch
`agent/codex/OIW-901-ci-e2e`

## Worktree
`../oiw-core`

## Objective
Make the 22-spec Playwright suite a CI gate (it currently runs only in
lead/agent local runs), and make it deterministic: fix the flaky
`security.spec.ts` "tampered cookie" sub-step and any other flake
surfaced by a 3× CI run.

## Inputs
- `AGENTS.md`, `.github/workflows/` (quality job w/ Postgres service),
  `apps/web/playwright.config.ts`, `apps/web/e2e/security.spec.ts:37`
  (failing sub-step: expects redirect to /demo after tampering the
  session cookie; intermittently lands on the real workspace overview —
  suspected race between cookie mutation and navigation, or the tampered
  value still verifying because of how the test mutates it),
  `docs/DEPLOYMENT.md` (env vars CI must set: SESSION_SECRET,
  OIW_RATE_LIMIT_IP_SALT, OIW_TRUSTED_PROXY_HEADER=none, DATABASE_URL)

## Owned Paths
- `.github/workflows/` (new e2e job or step: build web, migrate, seed,
  run Playwright with Chromium; artifacts on failure: traces/screenshots)
- `apps/web/e2e/` + `apps/web/playwright.config.ts` (determinism fixes
  only; no assertion weakening — a flaky security assertion must become
  a strict one)
- `docs/agent-runs/OIW-901.md`; lockfile only if regeneration needed

## Prohibited Paths
- Product code (BLOCKED protocol / NEEDS_REVIEW if a real defect is
  found behind the flake), `packages/*`, `scenario-packs/`, `SESSION.md`,
  `docs/tasks/`.

## Functional Requirements
1. CI: Playwright job runs on every PR against dockerized Postgres with
   migrations + `demo:seed`; caches browsers; uploads trace/screenshots
   on failure; required for merge alongside `quality`.
2. Root cause the tampered-cookie flake (reproduce with `--repeat-each`);
   fix the test's determinism (e.g. await cookie set + explicit
   navigation, assert response status/redirect chain rather than a timed
   URL check) — the assertion must remain "tampered cookie is rejected".
3. Run the full suite `--repeat-each=3` locally and in CI; any other
   flake found gets the same treatment; document each.
4. Resource discipline: CI job uses a single worker if needed for
   stability; document the runtime.

## Acceptance Criteria
- CI e2e job green 3× consecutively on the PR; `--repeat-each=3` green
  locally; security assertions strict; `pnpm lint && typecheck && test &&
  build` pass.

## Required Commands
`pnpm lint && pnpm typecheck && pnpm test && pnpm build && (cd apps/web && pnpm exec playwright test --repeat-each=3)`
