# Task OIW-904: Product Analytics Events and Assessment CTA (FR-120/121)

## Owner
Codex (high reasoning)

## Branch

## Worktree

## Objective
Deliver the deferred FR-120/121: first-party engagement analytics for the
PRD §23.1 event list and the "Adapt this workflow to your organisation"
assessment form (PRD §23.2), with a pluggable submission sink so the
owner's destination decision can be wired later without code changes.

## Inputs
- `AGENTS.md`, PRD §23, FR-120/121, `docs/PLAN_AMENDMENTS.md` A7/A9,
  `docs/UX_SPEC.md` (`/adapt` screen + CTA placements), `docs/SECURITY.md`
  (rate limits, no PII beyond what the form asks, no third-party
  trackers by default), `apps/web/src/app/adapt/`, OIW-810 limiter

## Owned Paths
- `packages/application/` (analytics event service; assessment
  submission service + `SubmissionSink` interface with a Postgres-table
  sink + a log/no-op sink; email/webhook sinks as interfaces only)
- `packages/persistence/` ONLY for two additive tables (analytics_events,
  assessment_submissions) + migration — you are this task's migration
  owner
- `apps/web/src/lib/server/` + `/adapt` server action + a minimal
  client-side event emitter hooked into the §23.1 events (tour steps,
  lens switch, process/review/approve, CTA open, submit)
- `tests/security/` (rate limit, PII handling, no cross-workspace),
  `apps/web/e2e/` (CTA submit journey)
- `docs/DEPLOYMENT.md` (sink configuration section), `docs/agent-runs/OIW-904.md`

## Prohibited Paths
- `packages/contracts/`, engines, SDK, `scenario-packs/`, UI restyling,
  `SESSION.md`, `docs/tasks/`.

## Functional Requirements
1. Analytics: server-side event ingestion for the §23.1 list, workspace/
   session-scoped, no third-party script, no IP storage (reuse the
   HMAC-hash approach), rate-limited, queryable via a small admin script
   (`pnpm analytics:summary`).
2. CTA form per §23.2 fields incl. "scenario being viewed" auto-filled;
   validation; synthetic-data + privacy notice; submission stored via
   the configured sink (`OIW_ASSESSMENT_SINK=postgres|log`, default
   postgres); confirmation state; audited.
3. Tests: submission validation, sink selection, rate limit, e2e journey.

## Non-Goals
No email/webhook sink implementation (interfaces + docs only, pending
owner decision). No dashboards for analytics.

## Acceptance Criteria
- Events recorded for a full guided tour run; CTA submission stored and
  visible via the summary script; all gates + e2e green; CI green.
