## Objective
Implement the synthetic guest-workspace lifecycle and the pack-driven seed
and reset system in `packages/application`, wired to `pnpm demo:seed` and
`pnpm demo:reset`. Combines PRD tasks OIW-105 and OIW-106.

## Background
Wave 1 exit criteria (PRD §26 Wave 1): selecting a pack creates an isolated
workspace, seed data loads, reset reproduces the identical starting state
(FR-004/005). ADR-007 defines the session design (signed httpOnly cookie →
workspace ID; TTL expiry). Consume: `@oiw/contracts` v1.1 (frozen),
`@oiw/persistence` repositories (merged), `@oiw/scenario-sdk` registry
(merged). Pack fixture content (OIW-004b) is not merged yet — build against
the registry/fixture interfaces and test with scenario-sdk-style test packs;
wiring to the real three packs happens automatically once OIW-004b lands.

## Functional Requirements
1. Workspace service: create a guest workspace for a pack id (slug, mode
   `guest`, `active_pack_id`, TTL/`reset_at` per ADR-007); expire/cleanup
   function for workspaces past TTL.
2. Session tokens per ADR-007: signed, httpOnly-cookie-ready value binding
   session → workspace ID (framework-agnostic utility — cookie setting
   itself is the web app's job in Wave 2); include signature verification
   and tamper tests.
3. Seed service: given a workspace + a loaded `ScenarioPack`, load the
   pack's seed/demo fixtures (artifacts + pre-existing entities/events/cases
   the pack declares) through the persistence repositories, deterministically
   (stable IDs → identical database state on every run; write an audit entry
   for the seed action).
4. Reset service: restore a workspace to the exact post-seed state (delete
   derived records, re-seed; audit entry recorded; FR-005 identical-state
   guarantee tested by seeding twice and diffing).
5. `pnpm demo:seed --pack <id>` and `pnpm demo:reset --workspace <slug>`
   CLI scripts against the docker Postgres.
6. Workspace isolation: seeding workspace A must not touch workspace B
   (test it).

## Non-Goals
No HTTP routes/UI (Wave 2). No rate limiting (Wave 4). No real pack content
authoring. No queue/cron for TTL cleanup (expose the function; scheduling
comes later).

## Acceptance Criteria
- `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm architecture:check` pass (docker Postgres up).
- Determinism test: two seeds of the same pack into fresh workspaces yield
  identical row sets (modulo workspace ID).
- Reset test: post-reset state equals post-seed state exactly.
- Isolation and token-tamper tests pass.
- CI green.
