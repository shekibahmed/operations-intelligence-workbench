## Functional Requirements
1. Case engine (FR-070): create cases from pending `create-case` outcomes
   per pack case definitions + workflow; state transitions validated
   against the workflow (guards via the fact catalogue; prohibited
   transitions rejected); severity/priority/owner/due date from definition
   parameters; audit every transition with cause.
2. Action items (FR-071): from `create-action` outcomes and case
   definitions; ownership, status, due date; completion recorded with
   optional evidence segment references.
3. Decision engine (FR-080): from `propose-decision` outcomes; proposal,
   rationale (from rule trace), risk level, approval policy from pack rules;
   status flow proposed → awaiting-approval → approved/rejected/
   more-information-required.
4. Approval enforcement (FR-081, ADR-005): applying an approval records the
   Approval row (approver = session identity semantics, comment, timestamp)
   and only then transitions the Decision; high-risk decisions can NEVER
   auto-approve — adversarial test attempting service-level bypass must
   fail (complementing the existing DB-boundary test).
5. Closure requirements (FR-072): a case cannot close unless its pack
   closure requirements are satisfied (action-completed, evidence-present,
   decision-approved, observation-reviewed); tested both ways.
6. Orchestration: extend the advance pipeline so a processed+reviewed
   artifact flows automatically through events→rules→signals→cases/actions/
   decisions (synchronous, idempotent); the A-142 storyline integration
   test now ends with: critical case open, inspection action assigned,
   hold-from-service decision awaiting approval; approving it updates
   case/audit; rejecting records outcome.
7. Gold parity: case/action/decision/approval expectations in the pack's
   evaluations for smoke + A-142 demo thread match exactly.
