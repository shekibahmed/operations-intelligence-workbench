## Functional Requirements
1. Entity list + entity detail/timeline (PRD §20.6, FR-091): attributes,
   status, related artifacts, event history, open/closed cases, signals —
   chronological timeline with links; created-via-review entities appear
   (closes the OIW-408 known limitation).
2. Signals surfaced per UX_SPEC (overview widgets where wired, case detail,
   entity timeline) with severity + triggering rule link.
3. Case list + case detail (PRD §20.5): all sections per spec — summary,
   status, priority, owner, SLA, related entities, evidence, timeline,
   signals, action items, decisions, approval history, closure
   requirements (with satisfied/unsatisfied state), technical trace link.
4. Decision centre (PRD §20.7): each decision with proposed action, risk
   level, rationale, supporting evidence, triggering rule, required
   approver; Approve / Reject / Request more information actions with
   confirm dialogs, session-validated, audited; approval history visible.
5. Technical rule-trace screen (`/technical/rules/[id]`): real rule
   evaluation traces (from OIW-501's persisted traces): rule id/version,
   condition tree results, facts, actions, rationale.
6. Lens behaviour, accessibility (§16.3), empty/loading/error states, pack
   labels throughout — same standards as prior UI tasks.
7. Tests: component tests per screen; extend Playwright: after review
   acceptance, walk entity timeline and (if engines are merged at your
   time) case → decision → approve.
