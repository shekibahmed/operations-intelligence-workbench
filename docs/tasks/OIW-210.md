## Functional Requirements
1. Server-side data access from apps/web route handlers/server components
   using `@oiw/persistence` + `@oiw/application` (DATABASE_URL env;
   document local run: docker compose up -d, pnpm db:migrate).
2. Guest session per ADR-007: signed httpOnly cookie via the application
   package's token utilities; every workspace route validates the cookie
   maps to the requested workspace slug, else redirects to /demo (no
   cross-workspace access — test it).
3. `/demo/[pack]` Start action: creates + seeds a real workspace for that
   pack (demo fixture set), sets the session cookie, redirects per UX_SPEC
   entry intent (guided → inbox, explore → overview).
4. Inbox: real artifacts from the seeded workspace (source, type, received
   time, processing status columns); pagination or sensible cap per NFR.
5. Artifact detail / technical inspector: raw artifact content, metadata,
   checksum, segments (locators rendered readably); extraction/rule-trace
   sections remain stub-marked until upstream lands.
6. Overview: real counts where data exists (artifacts, sources, workspace
   info, pack labels from the loaded pack — labels now come from the real
   registry, not stubs); remaining widgets stay stub-marked.
7. Reset action in the UI (workspace menu per UX_SPEC) calling the reset
   service, with confirm dialog.
8. Keep all lens/navigation/accessibility behaviour intact; keep
   empty/loading/error states real (loading via suspense/streaming or
   equivalent).

## Non-Goals
No processing trigger UI (needs OIW-301). No review queue/case/decision
data wiring. No rate limiting (Wave 4). No analytics.

## Acceptance Criteria
- With docker Postgres + migrations, `pnpm dev`: visiting /demo →
  Asset Reliability → Start creates a seeded workspace and the inbox lists
  its 25 demo artifacts with real data; artifact detail shows raw content
  and segments; reset restores initial state; a second browser session
  cannot access the first session's workspace URL (redirects).
- Unit/component tests for session-cookie guard and inbox data mapping;
  Playwright smoke of the selector→workspace→inbox journey (against local
  Postgres) if feasible in CI, else documented manual verification with
  screenshots in the PR.
- `pnpm lint && typecheck && test && build` pass; CI green.
