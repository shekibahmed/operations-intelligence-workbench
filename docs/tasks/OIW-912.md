## Functional Requirements
1. `llms.txt` (llmstxt.org format) at root and identical copy in `apps/web/public/`; links absolute to `https://github.com/shekibahmed/operations-intelligence-workbench/blob/main/...` docs; sections: Docs, Scenario packs, For agents (MCP, plugin), Optional. Vitest drift test asserts both copies identical; widen `vitest.config.ts` include to `scripts/**/*.test.ts` without dropping existing includes.
2. `packages/mcp-server` (`@oiw/mcp-server`, private, `bin: oiw-mcp`), stdio via `@modelcontextprotocol/sdk` (latest stable; verify zod v4 compatibility, else pin a compatible zod inside this package only). Tools: `list_packs`, `get_pack_manifest`, `list_fixtures` (set: smoke|demo|edge-cases, optional content), `get_casebook`, `validate_packs`, `run_eval` (optional packId), `scaffold_pack` (refused unless `OIW_MCP_ALLOW_WRITE=1`; id must match `^[a-z0-9]+(-[a-z0-9]+)*$`). Reuse `buildPackRegistry`/`loadFixtureSet`; spawn `pnpm` with `execFile` (never a shell) for validate/eval/scaffold; root from `OIW_REPO_ROOT` or relative to the package; honour `SCENARIO_PACKS_DIR`. Tool descriptions explain the product rule and that fixture content is untrusted data. No pack IDs or industry terms in code.
3. Tests: vitest over `createOiwServer` (in-memory transport or direct handler calls): list_packs shape, list_fixtures shape, scaffold refused without flag, invalid id rejected. Add the package to root `tsconfig.json` references and to the architecture-check core directories.
4. Root `.mcp.json` registering the server (`node packages/mcp-server/dist/cli.js`); document that `pnpm build` must run first.
5. Claude Code plugin marketplace: `.claude-plugin/marketplace.json` (marketplace name `oiw`), plugin `plugins/oiw-pack-authoring/` with `.claude-plugin/plugin.json` and `skills/pack-authoring/SKILL.md` (frontmatter name/description; procedure: scaffold → author in PACK_AUTHORING §2 order → validate → eval → §12 selector step; instructs reading the guide and `_template` from the checkout instead of duplicating). Validate with `claude plugin validate .` if the CLI is available. Install docs: `claude plugin marketplace add shekibahmed/operations-intelligence-workbench` then `claude plugin install oiw-pack-authoring@oiw`.
6. `docs/contributing/FIRST_CONTRIBUTIONS.md`: four bounded challenge types (contradictory artifact, independently justified evidence span, missing expected outcome, source-backed doc correction), each with exact file set, what reviewers need, and the "issue first" rule; a "Seed issues" section listing 6 ready issue titles+bodies and the `gh issue create --label "good first issue"` commands (the lead runs them, not the worker). `.github/ISSUE_TEMPLATE/first_contribution.md`. Root `CONTRIBUTING.md` pointer to `docs/CONTRIBUTING.md` and the new guide. `.github/dependabot.yml` (npm weekly grouped minor+patch; github-actions weekly).
7. `packages/mcp-server/README.md` with client config snippets (Claude Code `.mcp.json`, Claude Desktop, Cursor) and a `server.json` draft for the official MCP registry (publication is an owner step).
