## Objective
Create the Next.js application in `apps/web` with the full P0 route
skeleton, lens switcher, navigation and layout per `docs/UX_SPEC.md`,
rendering against static stub data. Combines PRD tasks OIW-201, OIW-203 and
OIW-204.

## Background
Wave 1. Backend engines land in Wave 2; this task builds the navigable shell
so every PRD §19 route renders with correct layout, lens behaviour, and
empty/loading/error states. Contracts are frozen — type stub data with
`@oiw/contracts` types where applicable.

## Functional Requirements
1. Next.js (App Router) app `apps/web` wired into the workspace; `pnpm dev`
   and `pnpm build` work from the root.
2. All PRD §19 routes exist and render: `/`, `/demo`, `/demo/[pack]`,
   `/w/[workspace]/{overview,inbox,review,cases,cases/[caseId],entities,entities/[entityId],decisions,technical/artifacts/[id],technical/rules/[id],audit,about-pack}`, `/adapt`.
3. Lens switcher per UX_SPEC: `?lens=` query param, default per route,
   persists across navigation; one nav component, lens changes presentation
   not reachability.
4. Layout per UX_SPEC: primary navigation, breadcrumbs (root → `/overview`),
   synthetic-data notice placement, persistent "Adapt this workflow" CTA
   (no tracking — A7).
5. Static typed stub data (small in-repo fixtures) so each screen shows its
   populated state; plus reachable empty, loading and error states per
   UX_SPEC (may be demonstrated via stub variants).
6. Tablet + desktop responsive per UX_SPEC; keyboard navigable; accessible
   names; state never conveyed by colour alone (PRD §16.3).
7. Basic component tests for the lens switcher and navigation behaviour;
   a Playwright smoke test (routes render) is welcome but optional this wave.

## Non-Goals
No real data fetching, no database, no pack registry wiring (Wave 2), no
guided tour (OIW-206), no dashboards beyond static A5 widget placeholders,
no auth.

## Acceptance Criteria
- `pnpm lint && pnpm typecheck && pnpm test && pnpm build` pass from root.
- Every §19 route renders without error in `pnpm dev`.
- Lens is URL-persisted and switching never loses the current route.
- No industry-specific copy in components — labels come from stub
  pack-label objects typed per contracts.
- Screenshots of overview, inbox, review, case detail and decision centre
  attached to the PR.
