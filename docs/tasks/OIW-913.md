# Task OIW-913: Walkthrough videos, trailer and README hero GIF

## Owner
Claude Code lead (Opus orchestrator) with a Sonnet implementation worker.

## Branch
`agent/claude/OIW-913-walkthrough-media`

## Worktree
Isolated sibling worktree; location recorded in the lead session only.

## Objective
A reproducible, opt-in pipeline that records each pack's guided tour from the real app at human pace and produces captioned MP4 walkthroughs with soft background music, a ~25 s trailer, posters and a README hero GIF.

## Background
Traction sprint 2026-10-18. People with short attention spans want to watch how it works. Existing patterns: `scripts/casebook/capture.ts` (server orchestration), `apps/web/playwright.casebook-capture.config.ts` + `apps/web/e2e/casebook-capture.spec.ts` (env-gated capture), `apps/web/e2e/accessibility.spec.ts` (three-pack tour walk), `apps/web/e2e/north-star.spec.ts`.

## Inputs
The files above, `apps/web/playwright.config.ts`, `docs/DEMO_SCRIPT.md`, `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`.

## Owned Paths
`apps/web/playwright.media.config.ts`, `apps/web/e2e/media-capture.spec.ts`, `apps/web/e2e/media/**`, `scripts/media/**`, `docs/media/` (all except `CREDITS.md`, owned by OIW-911), root `package.json` (add `media:capture`, `media:encode` scripts only), `.gitignore` (media lines only), this packet, `docs/agent-runs/OIW-913.md`.

## Prohibited Paths
`scripts/casebook/**` (copy patterns, never edit/import capture.ts), existing e2e specs and configs, lockfile, README.md, SESSION.md, apps/web/src.

## Functional Requirements
1. Capture config throws unless `MEDIA_CAPTURE=1`, `MEDIA_CAPTURE_PORT`, `MEDIA_CAPTURE_OUT` are set; `workers: 1`, `retries: 0`, 1280×800, `slowMo` ~120. Spec self-skips without `MEDIA_CAPTURE=1` so CI and default runs are unaffected.
2. One test per pack walking the guided tour in the same order as accessibility.spec.ts; record with a manually created context (`recordVideo` 1280×800); human pacing (2–3 s beats on each tour panel, cursor glides, typed approval comment via `pressSequentially` delay ~45 ms); injected visible fake cursor (aria-hidden, pointer-events none); timestamp `marks` for each step written to `<pack>.marks.json`. Generic approval comment: "Reviewed the cited evidence; approving the proposed action (synthetic demo)."
3. `scripts/media/capture.ts`: verifies ffmpeg/ffprobe, builds (unless `MEDIA_SKIP_BUILD=1`), starts `next start` on a free port with `OIW_RATE_LIMIT_STORE=memory`, random SESSION_SECRET and the caller's DATABASE_URL, runs the capture config, then calls encode.
4. `scripts/media/encode.ts`: per pack H.264 (yuv420p, faststart) + AAC MP4 ≤ 9.5 MB (CRF ~27, two-pass bitrate fallback); music from `apps/web/public/media/ambience.mp3` looped, `volume≈0.18`, fade in 2 s/out 3 s; `--no-music` flag and automatic no-music if the file is absent; WebVTT captions from marks; poster JPG at the review step; trailer ~25 s from five asset-reliability segments (process → review accept → rule trace → approve → dashboard) with music; `docs/media/hero.gif` ≤ 7.5 MB from the trailer (palettegen/paletteuse, ~12 fps, 960 px; fallback 10 fps/800 px).
5. Outputs: commit `hero.gif`, `*.vtt`, `poster-*.jpg`, `*.marks.json`, `docs/media/README.md` (how to regenerate and publish: `gh release create media-latest ...` / `gh release upload media-latest docs/media/*.mp4 --clobber`); gitignore `docs/media/*.webm`, `docs/media/*.mp4`.
6. Run the full pipeline once locally (with music if `apps/web/public/media/ambience.mp3` exists on the branch, else `--no-music`) and report sizes/durations via ffprobe. Do NOT create or upload the GitHub release (lead does).
