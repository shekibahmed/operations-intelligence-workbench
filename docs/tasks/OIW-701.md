# Task OIW-701: Common Lifecycle Proof Across All Packs (M2 core)

## Owner
Codex (high reasoning)

## Branch
`agent/codex/OIW-701-common-lifecycle`

## Worktree
`../oiw-core`

## Objective
Prove pack neutrality (PRD §10.4, goal G1): a single parameterized
lifecycle integration test that runs EVERY pack through the complete
pipeline — seed → ingest+process fixtures → extraction gold parity →
advance (entities/events/rules/signals) → cases/actions/decisions →
approval-required checks — and fix the pack-data defects it surfaces in
process-exceptions and document-assurance. Product-owner priority: each
pack's primary demo storyline must run cleanly end to end, because guided
tours for both packs (OIW-702) build directly on this.

## Background
Asset-reliability is fully proven (9/9 smoke parity, A-142 storyline,
north-star e2e). The other packs' content is contract-valid (ambiguity
validator passes) but never executed. Expect OIW-110-class defects
(extractions missing required keys, gold/event-definition mismatches).
Primary storylines per narrative: process-exceptions — the B-2205/B-2210/
KM-LOT-448 supplier-lot escalation ending in a hold-affected-output
decision; document-assurance — the Project Falcon liability-cap conflict
ending in an accept-exception decision. `narrative/expected-outcomes.md`
is the read-only semantic truth.

- `AGENTS.md`, PRD §10.4/§12, `docs/PLAN_AMENDMENTS.md`,

## Owned Paths
- `packages/application/test/` (common lifecycle test, parameterized over
  the registry's packs) + `packages/test-support/` helpers
- `scenario-packs/process-exceptions/` and
  `scenario-packs/document-assurance/`: schemas/events, rules, workflows,
  extractions, evaluations, manifest — fix the MINIMUM needed, document
  each fix with its narrative justification
- `docs/agent-runs/OIW-701.md`; lockfile only if regeneration needed

## Prohibited Paths
- `scenario-packs/*/narrative/` (read-only), fixture artifact BYTES
  (checksums frozen), `scenario-packs/asset-reliability/` (already proven;
  it must pass the common test UNCHANGED — if it does not, the test is
  wrong, not the pack), `packages/*` implementation code (engines are
  proven; BLOCKED protocol if a genuine engine gap or contract gap
  surfaces), `apps/`, migrations, `SESSION.md`, `docs/tasks/`.

## Functional Requirements
1. Common lifecycle test: for each registry pack — seed a workspace;
   ingest+process every smoke fixture; assert extraction gold parity
   (full-shape, as asset-reliability does); advance; assert
   events/signals/cases/decisions against the pack's gold expectations;
   assert every pack has ≥1 decision whose approval policy requires human
   approval and that it cannot auto-approve; assert duplicate and
   abstention edge behaviour per pack edge fixtures.
2. Primary-storyline test per new pack: the supplier-lot escalation and
   liability-cap threads run demo fixtures end to end, ending with the
   named high-risk decision awaiting approval; approve path exercised.
3. Fix process-exceptions and document-assurance pack data until 1+2 pass;
   asset-reliability passes the same test with zero changes.
4. Wire the common test into `pnpm test` (and hence CI).

## Non-Goals
No tours (OIW-702). No UI. No engine changes. No new fixtures beyond
minimal gold/extraction corrections.

## Acceptance Criteria
- Common lifecycle test green for ALL THREE packs; asset-reliability
  untouched by this task's diff.
- Both primary storylines end at their awaiting-approval decision and
  survive the approve path.
- `pnpm lint && typecheck && test && build && validate:packs && architecture:check` pass; CI green.
- Agent-run documents every pack-data fix with narrative justification.

## Required Tests
The common lifecycle test itself + storyline tests.
