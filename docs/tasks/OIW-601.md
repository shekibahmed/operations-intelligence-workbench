## Objective
Implement the metric evaluation service: pack metric definitions
(parameterizations of a small fixed set of core aggregation queries, per
amendment A5) evaluated workspace-scoped for dashboard consumption. PRD
task OIW-601 under the A5 constraint.

## Background
Final M1 backend piece. Packs ship `dashboards/metrics.json` (list of
metric definitions with id/name/description/classification/aggregation/
parameters/format — inspect all three packs). Widgets reference metrics by
`parameters.metricId`. The metrics files currently have no runtime
contract — same OIW-108/109 pattern: this packet PRE-AUTHORIZES an
additive `MetricDefinition` contract refinement (v1.5) + SDK catalogue +
validator enforcement (widget metricId references must resolve). Metric
classification (observed/calculated/estimated/hypothetical) must flow
through per PRD §7.9/§9.14.

## Functional Requirements
1. Closed aggregation vocabulary (A5): count / count-by-field /
   count-where / trend-over-time (bucketed counts) / sla-derived
   (due-date buckets) over the canonical objects (cases, signals,
   decisions, action items, events, artifacts) with declarative
   parameters (filters limited to schema fields + severity/status/type,
   time windows). No arbitrary queries.
2. Metric contract: id, name, description, classification
   (observed|calculated|estimated|hypothetical), aggregation kind,
   parameters, format. Validator: every dashboard widget `metricId`
   resolves to a defined metric; unknown aggregation kinds rejected.
3. Evaluation service: `evaluateMetrics(workspaceId, pack, metricIds?)` →
   typed values (number, breakdown map, time series, table rows) +
   classification + format hints; workspace-scoped by construction;
   deterministic given DB state.
4. Hypothetical metrics: never computed from operational data — their
   definitions carry illustrative parameters (e.g. assumption inputs) and
   the service returns them flagged so UI must badge them (PRD §7.9).
5. Tests: unit per aggregation kind; integration against a seeded +
   advanced asset-reliability workspace asserting real counts (open
   cases, critical signals, pending decisions match the A-142 storyline
   state); all three packs' metric files validate.
