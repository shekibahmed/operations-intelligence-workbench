# Task OIW-108: Observation-Schema Contract (v1.2) and SDK Catalogue API

## Owner
Codex (high reasoning)

## Branch
`agent/codex/OIW-108-observation-schema-api`

## Worktree
`../oiw-core`

## Objective
Define the runtime contract for pack observation-schema files (contracts
v1.2, additive) and expose a validated observation-schema catalogue plus a
value-validation API from `@oiw/scenario-sdk`. This unblocks OIW-301
(see `docs/agent-runs/OIW-301.md`, follow-up item 1). Nothing else.

## Background
Pack `schemas/observations/*.schema.json` files currently have no runtime
contract — the SDK checks they exist and are valid JSON, then discards the
contents. OIW-301 needs, per active pack: a catalogue keyed by `schemaKey`
with value constraints and an optional confidence threshold, and a way to
validate a proposed observation value against its schema definition. This
is the authorized dedicated contract-change task (v1.2).

## Functional Requirements
1. `ObservationSchemaDefinitionSchema` in contracts: at minimum `schemaKey`
   (slug), `label`, value typing (e.g. string/number/date/enum/boolean with
   optional constraints: enum values, min/max, pattern), `required`
   evidence expectation, optional `confidenceThreshold` (0..1), optional
   `entityLink` hint (whether the value references an entity type). Fit the
   shape to what the three packs actually shipped — do not invent fields no
   pack uses; do not drop fields packs rely on.
2. SDK loader: parse + validate every observation-schema file at pack load;
   invalid files fail validation with file+path context (consistent with
   existing PackIssue behaviour); expose the typed catalogue publicly.
3. `validateObservationValue(definition, value)` returning ok/issues —
   pure, no I/O — for OIW-301 to call.
4. Pack validator (validate:packs) now also fails on observation-schema
   files that violate the contract; all three real packs must pass
   (normalise their files mechanically if needed).
5. Tests: contract valid/invalid cases; loader catalogue test against a
   test pack + the real asset-reliability pack; value-validation cases per
   value type incl. threshold field presence.
