## Objective
Create the complete evaluation, threat-model and quality plan before feature
implementation accelerates, so every P0 requirement has a named verification
method and every material threat has a mitigation and a test.

## Background
PRD §16 (NFRs), §21 (evaluation framework), §22 (AI safety), §31 Packet D.
Amendments A1 (fixture determinism), A4 (guest sessions, CI database) and A7
(scope re-staging) are binding. Documentation-only task.

## Functional Requirements
1. Testing pyramid: unit → contract → workflow → product (browser/Playwright),
   mapped to repository layout and commands (PRD §35).
2. Pack contract tests: what the common lifecycle test asserts against every
   pack (PRD §10.4).
3. Extraction evaluation: field precision/recall, classification accuracy.
4. Evidence-span evaluation: correctness criteria and tolerance.
5. Abstention evaluation: when abstaining is correct; scoring.
6. Entity-resolution evaluation: exact/alias/ambiguous cases (A7 scope).
7. Rule and workflow evaluation: rule-execution correctness, duplicate-event
   prevention, case-state correctness.
8. High-risk approval tests and explicit approval-bypass tests (attempt to
   reach approved state without human approval must fail).
9. Duplicate-artifact and workspace-isolation test designs.
10. Threat model covering all ten PRD §31 Packet D areas: untrusted
    documents, prompt injection, malicious pack configuration,
    cross-workspace access, unsafe rendering, secret exposure, approval
    bypass, audit manipulation, denial of service, unsafe external
    write-back. For each: threat, mitigation, verifying test.
11. Guest-session threat analysis for the A4 design (signed cookie →
    workspace scoping, TTL expiry, rate limiting).
12. **CI database strategy**: dockerized Postgres + Drizzle migrations +
    seeded fixtures for Playwright; no Supabase in CI (A4).
13. Security gates for public deployment; separation of public-demo risks
    from future client-deployment risks.
14. Accessibility and responsive review criteria (PRD §16.3).
15. Release checklist for M3/M4.

## Non-Goals
- No test code. No tooling configuration. No evaluation-runner implementation
  (that is a core-track task per A8).

## Acceptance Criteria
- Every P0 functional requirement (PRD §15) maps to ≥1 verification method
  (include the mapping table).
- Every material threat has a mitigation and a named test.
- AI evaluation measures evidence and abstention, not only extraction accuracy.
- Approval-bypass tests are explicit and adversarial.
- Public-demo risks and client-deployment risks are separated.
