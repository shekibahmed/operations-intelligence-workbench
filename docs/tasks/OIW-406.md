## Functional Requirements
1. Process action: on artifact rows/detail (per UX_SPEC), triggers
   processArtifact server-side for the session workspace; processing status
   updates in the inbox; failed processing shows the failure state with
   retry (NFR §16.1).
2. Review queue (FR-030): lists observations with reviewStatus
   pending/conflicting for the workspace; layout per UX_SPEC — raw source
   left with the evidence span highlighted via its locator (text-range
   highlight; page/table-cell/json-path rendered as labelled context),
   structured observation right with value, confidence, status badge,
   alternativeCandidates (selectable when present), extractor metadata.
3. Actions (FR-030/031): Accept, Correct (edit value; original preserved
   and shown as history), Reject, Mark insufficient evidence; reviewer
   recorded (guest session identity per ADR-007 semantics), timestamps;
   ambiguous-entity items allow choosing a candidate. All server actions
   session-validated.
4. Correction semantics per ADR-006: corrections feed downstream normally
   pre-event; UI copy must not promise retroactive rewrites.
5. Technical inspector: extraction section now real — proposed
   observations, confidence, evidence coordinates, validation results,
   provider metadata, processing trace (was stub-marked in OIW-210).
6. Accessibility per §16.3 (keyboard path through review actions, focus
   management, no colour-only state). Empty/loading/error states real.
7. Tests: component tests for review actions + evidence highlighting
   mapping; extend the Playwright journey: process the brake-fault demo
   artifact → review the ambiguous observation → accept → status updates.
