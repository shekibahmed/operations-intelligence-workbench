## Objective
Produce an implementation-ready UX specification for the neutral platform and
its three demonstration lenses, such that a frontend agent can implement
every P0 route without inventing product behaviour.

## Background
PRD §8 (lenses), §13 (north-star journey), §19–20 (routes and screens), §31
Packet B. Amendments A5 (widget catalogue) and A7 (scope re-staging) are
binding. This task is documentation-only.

- `AGENTS.md`, `docs/PRD.md` (§6, §8, §13, §19, §20, §22.5, §23),
  `docs/PLAN_AMENDMENTS.md`

## Owned Paths
- `docs/UX_SPEC.md`, `docs/DEMO_SCRIPT.md`, `docs/ux/`,

## Prohibited Paths

## Functional Requirements
1. Complete information architecture and route map (PRD §19); navigation and
   breadcrumb behaviour; lens persistence in the URL.
2. Scenario-selection journey (PRD §13.1–13.2) including synthetic-data
   notice placement.
3. Leadership, Operations and Technical lens definitions — same underlying
   state, per PRD §8.4.
4. Every P0 screen specified (PRD §20): scenario selector, leadership
   overview, artifact inbox, review queue, case list, case detail, entity
   detail, decision centre, technical inspector, audit explorer. For each:
   user goal, information hierarchy, components, states, actions, empty
   state, loading state, error state, tablet/desktop behaviour, accessibility
   considerations (PRD §16.3).
5. Widget specs constrained to the A5 fixed catalogue (~8 widget types) —
   define each widget type's anatomy and configuration surface.
6. Metric-provenance labelling treatment: Observed / Calculated / Estimated /
   Hypothetical each get a distinct, always-visible badge; hypothetical
   values must never read as measured results (PRD §7.9).
7. The full Asset Reliability guided demonstration (PRD §13, step by step) in
   `docs/DEMO_SCRIPT.md`; shorter Leadership-only outlines for Process
   Exception and Document Assurance (A7).
8. Language rules preventing industry terminology in generic components; how
   pack labels flow into UI copy.
9. Contextual "Adapt this workflow" CTA placement (UI spec only — tracking is
   deferred per A7).
10. Text wireframes for each P0 screen in `docs/ux/`.
11. Screenshot requirements for future UI PR reviews.

## Non-Goals
- No application code, no component library selection, no visual design
  system (colour/type) beyond layout and hierarchy, no P1/P2 screens.

## Acceptance Criteria
- Every P0 route is implementable without inventing product behaviour.
- The three lenses demonstrably describe the same underlying state.
- Technical lens exposes evidence, confidence, rule trace and audit.
- Leadership lens never presents hypothetical ROI as measured results.
- Operations lens shows owners, states, due dates and approvals.
- No screen is tied to one industry; all domain language arrives via pack labels.

## Required Tests
None (documentation task). Internal consistency check: every route in the
route map has a screen spec; every screen spec names its lens(es).
