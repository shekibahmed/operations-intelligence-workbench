## Objective
Full click-through guided tours for Process Exception Management and
Document Assurance — same quality as the Asset Reliability tour — each
walking its pack's primary storyline end to end and finishing at the human
approval moment, plus a Playwright journey per pack. Product-owner request
(2026-09-01) superseding the A7/L2 leadership-only deferral.

## Background
OIW-701 (merged) proves both packs' lifecycles end to end:
process-exceptions' supplier-lot escalation (B-2205/B-2210/KM-LOT-448 →
hold-affected-output decision) and document-assurance's Project Falcon
liability-cap conflict (→ accept-exception decision). The tour framework
(typed step list, overlay, sessionStorage resume, keyboard/focus handling)
exists from OIW-602 — reuse it; do not build a second mechanism. Read
`docs/agent-runs/OIW-701.md` for exactly which fixtures drive each
storyline and any semantics clarified during the lifecycle fixes.

## Functional Requirements
1. Tour step lists for both packs mirroring the PRD §13 arc in each pack's
   own vocabulary (labels from pack labels.json, never hardcoded industry
   copy in shared components): select pack → inbox → process the
   storyline's source artifact → review (each pack's review moment: the
   ambiguous/conflicting observation its edge narrative calls for) →
   accept → event/signal → case → the pack's high-risk decision → approve
   → dashboard update → technical trace.
2. `/demo/[pack]` "Start guided tour" works for all three packs (currently
   asset-reliability only — check and fix the entry wiring); tour selection
   per pack manifest `demo.tour`/defaults where applicable.
3. Same UX guarantees as the existing tour: dismissable, resumable
   (sessionStorage, per-pack key), keyboard accessible, focus-managed,
   step targets exist on every referenced screen.
4. DEMO_SCRIPT.md: expand both pack sections from leadership outlines to
   the full click-through scripts implemented.
5. Playwright: one journey per pack driving the real tour to the approval
   step and asserting real state (event/signal/case/decision) — additive
   to the existing 7 specs; all must stay green.
6. Component tests for per-pack step lists (targets resolve, step count,
   vocabulary from labels).
