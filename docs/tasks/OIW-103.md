## Background
Wave 1. The registry is how the application discovers and loads packs; the
validator is the neutrality enforcement point (PRD §11.3, FR-001/002).
Contracts are frozen — consume `@oiw/contracts` as-is; if a contract blocks
you, mark BLOCKED rather than changing it. Note: pack directories currently
contain only `narrative/` content (OIW-004a); schema-bound pack files arrive
with OIW-004b, so this task must ship its own test fixtures.

## Functional Requirements
1. `loadPackFromDirectory(path)`: reads `manifest.yaml` + referenced files
   (labels, schemas, workflows, rules, dashboards) into a typed
   `ScenarioPack` per `@oiw/contracts`, with precise, path-annotated errors.
2. Validation per PRD §11.3: manifest validation; schema validation;
   workflow-state validation (transitions reference declared states; closure
   requirements well-formed); rule-reference validation (rules reference
   declared event types and only fact-catalogue facts); dashboard-widget
   validation against the A5 fixed widget catalogue; fixture/extraction
   cross-check (every fixture artifact has a checksum-keyed expected
   extraction per A1) — tolerate absent fixture dirs with a warning until
   OIW-004b lands.
3. Registry: enumerate `scenario-packs/*`, load valid packs, report invalid
   ones without crashing; stable ordering; pack lookup by id+version.
4. `scripts/validate-packs.ts` runs the validator over `scenario-packs/`
   and exits non-zero on errors (packs with only `narrative/` content are
   skipped with a notice, not failed, until OIW-004b).
5. Test fixtures: a minimal valid pack and several invalid packs (bad
   manifest, unknown fact in rule, undeclared workflow state, unknown
   widget type, missing expected-extraction) under the package's test dir.
