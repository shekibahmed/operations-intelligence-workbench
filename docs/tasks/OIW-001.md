## Objective
Create the repository foundation and freeze v1 of the shared platform
contracts so all downstream Wave 1+ work can proceed in parallel. This task
absorbs PRD task OIW-002 (amendment A6).

Everything on the critical path depends on this task. PRD §17 (architecture),
§18 (repo structure), §31 Packet A. Amendments A1–A5 and A8 in
`docs/PLAN_AMENDMENTS.md` are binding.

## Functional Requirements
1. pnpm TypeScript monorepo per PRD §18 with a task runner (Turborepo or
   plain pnpm scripts — your call, record it).
2. Canonical Zod contracts in `packages/contracts/` for: Workspace,
   ScenarioPack, Source, Artifact, ArtifactSegment, Entity, Observation,
   OperationalEvent, Signal, Case, ActionItem, Decision, Approval,
   MetricDefinition, AuditEntry (PRD §9). Provenance fields per PRD §7.4.
3. Scenario Pack manifest schema (PRD §11) including labels, entity/event
   types, workflows, rules, dashboards, fixtures, evaluation sets.
4. Workflow-definition schema: states, transitions, guards (fact-catalogue
   facts only), closure requirements (amendment H3 context, PRD FR-072).
5. Rule schema per PRD §17.5 plus **closed fact catalogue v1** (amendment
   A2): event fields, observation lookups by schema key, core-computed
   aggregates (document each fact).
6. **Fixture expected-extraction contract** (amendment A1):
   `ExtractionResult` keyed by artifact checksum, including evidence spans,
   confidence, and abstention states (PRD §22.3).
7. `IntelligenceProvider` interface per PRD §17.4.
8. Placeholder exports in all stub packages that compile.
9. ADRs in `docs/decisions/`: 001 modular monolith, 002 scenario packs,
   003 provenance model, 004 deterministic demo (incl. A1), 005 human
   approval, 006 correction semantics (A3), 007 guest-session isolation (A4).
10. `docs/ARCHITECTURE.md` (boundaries, system flow, A4 session design) and
    `docs/DOMAIN_MODEL.md` (object model + lifecycle).
11. Scripts/placeholders wired for: `pnpm lint`, `typecheck`, `test`, `eval`,
    `build`, `validate:packs`, `architecture:check`.
12. `architecture:check` must at minimum scan core packages for prohibited
    industry terms (PRD §10.1) and prevent pack imports into core domain code.
13. GitHub Actions CI running install, lint, typecheck, test, build on PRs.

## Non-Goals
- No UI beyond stubs. No ingestion implementation. No live AI provider.
- No database schema/migrations (Wave 1, OIW-101). No scenario-specific logic.

## Acceptance Criteria
- `pnpm install`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` all pass.
- All domain contracts have unit tests (valid + invalid cases).
- An example valid pack manifest passes validation; an invalid one fails with
  precise, useful errors.
- A rule referencing an unknown fact fails validation.
- No industry-specific type or term exists in `packages/domain` or
  `packages/contracts` (`architecture:check` proves it).
- CI workflow runs green.

## Required Tests
- Unit tests per contract schema; manifest validation tests; fact-catalogue
  validation tests; extraction-contract round-trip test.

## Required Commands
`pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm architecture:check`
