## Background and Functional Requirements
1. **Build-time `NEXT_PUBLIC_SITE_URL`.** `apps/web/next.config.ts` reads it at build time (HSTS header, and any `NEXT_PUBLIC_*` inlining), but the `Dockerfile` declares no `ARG`, so Render's env var never reaches `next build`; the live demo's sitemap/robots may print the localhost fallback. Verify what the deployed https://operations-intelligence-workbench.onrender.com/sitemap.xml and /robots.txt print today (curl). Add `ARG NEXT_PUBLIC_SITE_URL` (+ `ENV` for the build stage only) to the Dockerfile builder stage; document in docs/DEPLOYMENT.md §9 that Render passes service env vars as Docker build args. Confirm robots/sitemap read the URL at request time or build time and make both correct.
2. **Pack scaffold argument safety.** `scripts/pack-scaffold.ts` must reject values that look like options (leading `-`) and control characters for `--name`/`--description`, and write YAML string values with `JSON.stringify` (valid YAML) so quotes/colons cannot break the manifest. Add tests (vitest under `scripts/`; root `vitest.config.ts` already includes `scripts/**/*.test.ts` once OIW-912 merges — if not on main yet, add a test file and confirm it runs).
3. **Architecture doc.** Add `packages/mcp-server` to the package table/boundary map in `docs/ARCHITECTURE.md` (stdio MCP server over scenario-sdk; read-mostly; writes only via `OIW_MCP_ALLOW_WRITE=1` scaffold). If OIW-912 is not yet on main when you start, write the row anyway from its packet (docs/tasks/OIW-912.md on branch origin/agent/claude/OIW-912-agent-surface).
4. **Analytics event loss (north-star flake).** CI run 39080887437 (PR #17) failed once in three repeats: `apps/web/e2e/north-star.spec.ts` step "the completed guided tour is measurable through first-party analytics" received events without `scenario-selected` within 5 s. Find the root cause: likely the client sends the event (fetch without `keepalive` or `navigator.sendBeacon`) and then navigates, cancelling the request. If so, fix the client sender (apps/web/src/components/analytics/* or lib) to use `sendBeacon` with a `fetch(..., {keepalive: true})` fallback, keep the server route contract unchanged, and add a unit test. If the cause is the test instead, fix the test. Evidence first, then fix. Run north-star with `--repeat-each=5` under the lock to show stability.
