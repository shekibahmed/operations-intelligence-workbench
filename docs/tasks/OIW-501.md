## Functional Requirements
1. Entity resolution (A7 scope): resolve accepted observations that
   reference entities to seeded Entities by exact external_reference /
   display_name match plus pack-supplied aliases (entity `attributes.aliases`
   if present); ambiguous match (>1 candidate) → observation
   `reviewStatus: "conflicting"` with alternativeCandidates populated,
   never silently attached (FR-041); no fuzzy scoring.
2. Event assembly (FR-050): assemble OperationalEvents from accepted (or
   not-required) observations per the pack's event schemas; evidence
   segment links carried through; idempotent (re-running does not duplicate
   events); exact-duplicate artifacts (flagged by ingestion) produce NO new
   event, recorded in audit (duplicate-event prevention per §21.3).
3. Rule engine (FR-060): evaluate pack RuleDefinitions against events using
   fact catalogue v1 (event fields, observation lookups, core aggregates
   incl. related-event-count with eventType/withinHours); condition
   combinators all/any/not; every evaluation produces a persisted rule
   trace (rule id, version, condition results, fired actions, rationale)
   for the Technical Lens.
4. ActionExecutor seam: `create-signal` and `flag-review` executors
   implemented here; `create-case` / `create-action` / `propose-decision`
   actions are recorded as pending rule outcomes (persisted, auditable) for
   batch C to execute — document the seam in the README.
5. Signals (FR-061): created with severity, links to triggering rule,
   source event(s) and evidence; audit entries throughout.
6. Orchestration: `advanceArtifact(workspaceId, artifactId)` (or extend the
   existing processing service) runs resolution → assembly → rules →
   signals for reviewed artifacts, synchronous, idempotent.

  yields the repeat-fault signal via the related-event-count aggregate, and
  a pending `propose-decision` rule outcome (hold-from-service) recorded
  for batch C.

  attachment. Duplicate artifact (edge-005) → no second event.
